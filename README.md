# PumpSharp

Read-only .NET decoding and quote maths for the Pump bonding-curve and
PumpSwap AMM programs on Solana.

- Decode `CreateEvent`, `TradeEvent`, `CompleteEvent` and
  `CompletePumpAmmMigrationEvent` from transaction logs.
- Decode `BondingCurve`, `Global`, PumpSwap `Pool`, `GlobalConfig` and
  `FeeConfig` accounts.
- Derive program addresses (bonding curve, creator vault, pool, configs).
- Quote bonding-curve, curve-v3 and PumpSwap trades with fees, including
  mayhem mode, boost pools and Token-2022 transfer fees.
- No dependencies, no signing, no keys and no network access. You fetch the
  bytes with your own RPC client and PumpSharp decodes them.

> Unofficial. Not affiliated with Pump.fun. Protocol layouts come from the
> official IDLs in `@pump-fun/pump-sdk` 4.3.1, and the quote maths is checked
> against vectors generated by running that SDK and `@pump-fun/pump-swap-sdk`
> 2.2.0. When Pump changes a program, this library can be out of date until a
> new release; see [Protocol drift](#protocol-drift).

## Install

```bash
dotnet add package PumpSharp --prerelease
```

Requires .NET 10.

## Example

```csharp
using PumpSharp;
using PumpSharp.Chain;

// 1. Decode a log line from a transaction that invoked Pump.
//    (Use PumpLogScope to keep only lines Pump itself emitted.)
var failure = PumpEventDecoder.DecodeLogLine(logLine, out var decoded);
if (failure == PumpDecodeFailure.None && decoded.Kind == PumpEventKind.Trade)
{
    var trade = decoded.Trade;
    Console.WriteLine($"{(trade.IsBuy ? "buy" : "sell")} {trade.TokenAmount} of {trade.Mint}");
}

// 2. Derive a mint's bonding-curve address, then decode the account bytes
//    you fetched with your own RPC client.
if (Pubkey.TryParse(mintAddress, out var mint)
    && PumpAddresses.TryBondingCurve(mint, out var curveAddress, out _))
{
    // Fetch curveAddress with your RPC client (getAccountInfo) to get accountBytes.
}

if (PumpAccountDecoder.DecodeBondingCurve(accountBytes, out var curve, out _) == PumpAccountDecodeFailure.None
    && PumpBondingCurve.TryQuoteBuy(curve.Reserves, quoteInUnits: 100_000_000, out var quote))
{
    // Core curve output before fees; see PumpBondingCurve.TryFee and
    // PumpCurveV3Quote for fee-inclusive quotes.
    Console.WriteLine($"0.1 SOL buys {quote.AmountOutUnits} raw token units");
}
```

Every decoder returns a named failure (`Truncated`, `TrailingBytes`,
`UnknownDiscriminator` and so on) instead of throwing. Event payloads that are
shorter or longer than the IDL layout are refused, so a changed layout is
reported rather than decoded into wrong values.

## How correctness is checked

| What | Checked against |
|---|---|
| Event and account layouts | The embedded official IDLs, field by field |
| Bonding-curve quotes | 228 vectors from `@pump-fun/pump-sdk` 4.3.1 |
| PumpSwap quotes and fees | 519 vectors from `@pump-fun/pump-swap-sdk` 2.2.0 |
| Curve v3, mayhem, boost, transfer fees, pool-v2 debits | Further vector sets generated from the same SDKs |
| PDA derivation | IDL seed bytes, plus an independent implementation (SolSharp) |

The vector files and the scripts that generated them are in
[`tests/PumpSharp.Tests/parity/`](tests/PumpSharp.Tests/parity/).
`PumpProtocolFingerprint.QuoteMathsParityVerified` covers only the routes listed in
the coverage audit there. It does not cover routes the library does not
implement, or how your own trades will execute.

## Protocol drift

`PumpProtocolFingerprint.Current` records the program ids, SDK versions and
SHA-256 of each embedded IDL. Store it next to anything you compute, and
re-check your results when it changes. `PumpDriftTracker` counts
discriminators no embedded IDL declares and decode failures by reason, so a
protocol upgrade shows up in the counts instead of as missing trades.

## Versioning

[Semantic Versioning](https://semver.org/). Before 1.0, minor versions may
